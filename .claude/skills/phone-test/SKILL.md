在真實手機上驗收這個 PWA。使用者是程式新手，每一步都要說清楚要做什麼、在哪裡做、預期看到什麼。

1. **先跑電腦端的檢查**：執行 `npm run check` 和 `npm run build`。有失敗就先停下來處理，不要請使用者測。
2. **確認已部署**（這台 VM 是 NAT，手機連不到 dev server，**不要啟動 server**）：
   - `git status` 確認沒有未 commit 的改動；`git log origin/main..main` 確認沒有未 push 的 commit。有的話先問使用者要不要 push。
   - `gh run list --limit 1` 確認最新一次部署成功（還在跑就用 `gh run watch` 等它）。
   - 請使用者用手機打開 https://pyondudu.github.io/draw-helper/ 。主畫面的 App 要**完全關掉再打開一兩次**才會換成新版。
3. **安全提醒**（每次都要講）：
   - 「開啟」「開啟抽選」會打開**真的** LINE 抽選。測試時不要按進行中那一輪的連結，除非真的要抽。
   - LINE 若出現加好友畫面，直接返回，不要加好友。
   - 測試按的「中了／沒中」會被記下來，可以到清單模式用下拉選單改回「未抽」。
4. **說明哪些已經自動測過**（不用請使用者再測）：
   - 兩個固定版本的筆數完全相符（`npm run check`）
   - 讀不到資料時顯示「資料讀取失敗」與「打開原頁面」，不會出現空清單
5. **手機測試清單**（Android 主畫面版必測；iPhone 用 Safari「分享 → 加入主畫面」的版本測）。請使用者逐項回報：
   - [ ] 打開 App 會自動讀到這一輪，顯示「N/N 那輪」、讀取時間、筆數；按「重新整理」會顯示「比上次讀取多了／和上次一樣」
   - [ ] 飛航模式下按「重新整理」：紅框「資料讀取失敗」＋「打開原頁面」按鈕
   - [ ] 設定頁：桃竹門市都在、其他縣市可展開加入、可個別取消門市；款式顯示「N 家可抽」，新款式標「新」
   - [ ] 首頁：狀態（尚未開始／進行中／已結束）、「共 N 筆要抽，已抽 M 筆」、每個想要的款式「已抽幾家／共幾家」，點開看得到各門市
   - [ ] 連續抽選：依開抽時間排序；未到時間時按鈕不能按並倒數；「全部抽完」只跑那一款
   - [ ] 按「開啟抽選」能跳到 LINE；從 LINE 回到 App 時畫面停在原本那一筆，「中了／沒中」還在
   - [ ] 按「中了」或「沒中」會跳到下一筆；「中了」的項目出現在首頁最上方
   - [ ] 清單模式：「只看想要的款式」「只看未抽」有效；下拉選單可改回按錯的結果
   - [ ] 關掉 App 再打開：已抽紀錄、中或沒中、想要的款式都還在
   - [ ] 從主畫面打開是全螢幕（沒有網址列）
6. **記錄結果**：測完後把結果（哪支手機、哪幾項通過、遇到的問題）寫進 `PROGRESS.md`，並提醒使用者有問題可以截圖給你看。
